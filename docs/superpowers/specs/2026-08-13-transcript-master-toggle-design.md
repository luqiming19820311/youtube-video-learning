# Transcript 总开关设计

## 目标

在侧边栏标题区域新增一个 `Transcript` 总开关，用来统一控制顶部的 `Transcript`、`Overview`、`Notes` 三个页签是否可以操作。

## 已确认的交互

- 开关默认关闭；首次安装或没有历史记录时，三个页签不可操作。
- 开启时，三个页签正常响应点击，现有字幕、概览懒加载和笔记行为保持不变。
- 关闭时，三个页签保留可见，但统一呈现禁用样式并且不可点击。
- 关闭时不请求字幕、不启动翻译、不显示已有 Transcript 内容，内容区显示开关关闭提示。
- 若关闭前字幕或翻译请求已经发出，其延迟响应必须失效，不能重新写回界面。
- 关闭开关不会清除本地缓存；重新开启时优先恢复缓存，避免重复消耗 Supadata 请求。
- 重新开启后，恢复三个页签操作，并为当前视频从缓存恢复或按需加载字幕。
- 播放器 `CC` 是 Transcript 的子功能：Transcript 开启并取得当前视频字幕后显示，Transcript 关闭时立即移除；重新开启后随字幕状态恢复，`CC` 自身仍默认关闭。
- 开关状态保存到 `chrome.storage.local`，重新打开侧边栏后保持上次选择。

## 界面结构

- 在视频信息与 `Settings` 按钮附近增加带文字标签的开关，标签为 `Transcript`。
- 使用原生按钮语义实现开关，并维护 `role="switch"` 和 `aria-checked`，确保键盘和辅助技术可识别。
- 关闭时，页签设置 `disabled` 和 `aria-disabled="true"`；CSS 降低对比度并使用不可用光标。
- 开关本身始终可操作，不受页签禁用状态影响。

## 状态与数据流

- 新增独立本地存储键保存布尔状态，不修改现有 `ytd_settings` 公共数据结构。
- 侧边栏初始化时先读取状态；没有历史值时按关闭处理。
- 用户切换开关时立即更新界面状态并异步写入本地存储。
- 侧边栏初始化、视频切换、YouTube Digest 按钮消息和重试入口均先检查开关，关闭时不得进入字幕请求管线。
- 每次开启生成请求代次令牌；关闭时令牌失效，所有延迟字幕响应和翻译响应均被忽略。
- `switchTab` 增加状态保护。即使点击事件或其他调用路径尝试切换，在开关关闭时也直接返回，避免只依赖 HTML 的 `disabled` 属性。
- 关闭开关不触发字幕获取、AI 分析、翻译或笔记加载，并隐藏结果区域。

## 错误处理

- 存储读取失败时回退为关闭，保持默认保护行为。
- 存储写入失败时保持本次页面中的开关状态，不阻断用户继续操作。

## 测试标准

- 无历史状态时开关默认关闭，三个页签不可用。
- 关闭后三个页签都具有禁用属性和禁用样式状态。
- 关闭时点击或直接调用页签切换不会改变活动页签，也不会触发 Overview 分析。
- 关闭状态初始化和视频切换不发送 `fetchTranscript`。
- 关闭前已发出的字幕请求返回后不会显示内容或启动翻译。
- 重新开启后页签恢复可操作，并优先恢复已有缓存。
- Transcript 开启且字幕加载完成后显示播放器 `CC`；关闭时清除播放器字幕层和 `CC`。
- 开关值会写入本地存储，重新初始化后正确恢复。
- 完整运行 `npm test`、`npm run check` 和 `npm run package`。

## 不在本次范围

- 不清除字幕、摘要、翻译或笔记缓存。
- 不改变 Transcript 内部的 `Original / 中文 / 双语` 模式。
